
# Документация REST API

## 1. Общие сведения

Базовый адрес: http://127.0.0.1:8000/api

Обмен данными между клиентом и сервером осуществляется в формате JSON. Сервер реализован на PHP, данные хранятся в PostgreSQL.

Для запросов с телом используется заголовок:

`Content-Type: application/json`

Для защищённых запросов необходимо передавать токен:

`Authorization: Bearer <token>`

## 2. Аутентификация

| Метод | Маршрут | Назначение | Код ответа |
|---|---|---|---|
| POST | /api/login | Вход в систему | 200 |
| GET | /api/me | Получение данных текущего пользователя | 200 |
| POST | /api/logout | Выход из системы | 204 |

Для входа необходимо передать электронную почту и пароль.

Пример тела запроса POST /api/login:

```json
{
    "email": "ivan@example.com",
    "password": "123456"
}
```

При успешном входе сервер возвращает токен и данные пользователя, включая его роль. Срок действия токена составляет 2 часа.

Пароли хранятся в виде хешей. В базе данных также хранятся хеши токенов. При выходе из системы токен отзывается.

## 3. Бронирования

| Метод | Маршрут | Назначение | Код ответа |
|---|---|---|---|
| GET | /api/bookings | Список бронирований | 200 |
| GET | /api/bookings/{id} | Получение бронирования | 200 |
| POST | /api/bookings | Создание бронирования | 201 |
| PUT | /api/bookings/{id} | Изменение бронирования | 200 |
| PATCH | /api/bookings/{id} | Частичное изменение | 200 |
| DELETE | /api/bookings/{id} | Удаление бронирования | 204 |

### Параметры получения списка

| Параметр | Назначение |
|---|---|
| q | Поиск по теме встречи |
| status | Фильтрация по статусу |
| room_id | Фильтрация по идентификатору комнаты |

Примеры запросов:

- GET /api/bookings?q=IT
- GET /api/bookings?status=active
- GET /api/bookings?room_id=1

### Поля бронирования

| Поле | Тип | Назначение |
|---|---|---|
| id | integer | Идентификатор бронирования |
| room_id | integer | Идентификатор комнаты |
| user_id | integer | Идентификатор владельца |
| subject | string | Тема встречи |
| date | string | Дата в формате YYYY-MM-DD |
| start_time | string | Время начала в формате HH:MM |
| end_time | string | Время окончания в формате HH:MM |
| participants | integer | Количество участников |
| status | string | Статус бронирования |

Пример создания бронирования:

```json
{
    "room_id": 1,
    "subject": "Планирование проекта",
    "date": "2026-11-30",
    "start_time": "10:00",
    "end_time": "11:00",
    "participants": 4
}
```

Владелец определяется сервером по токену текущего пользователя.

Допустимые статусы:

- active — активное;
- done — завершённое;
- cancelled — отменённое.

Для отмены бронирования используется PATCH /api/bookings/{id}:

```json
{
    "status": "cancelled"
}
```

При сохранении проверяются существование комнаты, корректность даты и времени, вместимость комнаты, длина темы встречи и отсутствие пересечений с другими активными бронированиями.

## 4. Переговорные комнаты

| Метод | Маршрут | Назначение | Код ответа |
|---|---|---|---|
| GET | /api/rooms | Список комнат | 200 |
| GET | /api/rooms/{id} | Получение комнаты | 200 |
| POST | /api/rooms | Создание комнаты | 201 |
| PUT | /api/rooms/{id} | Изменение комнаты | 200 |
| PATCH | /api/rooms/{id} | Частичное изменение | 200 |
| DELETE | /api/rooms/{id} | Удаление комнаты | 204 |

Пример тела запроса для создания комнаты:

```json
{
    "room_number": "601",
    "capacity": 8,
    "location": "6 этаж",
    "equipment": "Проектор, Маркерная доска"
}
```

Номер комнаты должен содержать от 1 до 10 символов, вместимость должна быть положительным целым числом. Оборудование перечисляется через запятую.

Удаление комнаты, связанной с существующими бронированиями, запрещено.

## 5. Пользователи

| Метод | Маршрут | Назначение | Код ответа |
|---|---|---|---|
| GET | /api/users | Список пользователей | 200 |
| GET | /api/users/{id} | Получение пользователя | 200 |
| POST | /api/users | Создание пользователя | 201 |
| PUT | /api/users/{id} | Изменение пользователя | 200 |
| PATCH | /api/users/{id} | Частичное изменение | 200 |
| DELETE | /api/users/{id} | Удаление пользователя | 204 |

Пример тела запроса для создания пользователя:

```json
{
    "name": "Алексей Смирнов",
    "email": "alex@example.com",
    "password": "123456"
}
```

Имя должно содержать от 2 до 100 символов, адрес электронной почты должен быть корректным и уникальным. Длина пароля составляет от 6 до 72 байт.

При изменении пользователя доступны поля name и email.

## 6. Разграничение прав доступа

| Действие | Без входа | Пользователь | Администратор |
|---|---|---|---|
| Вход в систему | Да | Да | Да |
| Просмотр комнат | Нет | Да | Да |
| Просмотр бронирований | Нет | Да | Да |
| Создание бронирований | Нет | Да | Да |
| Изменение своих бронирований | Нет | Да | Да |
| Удаление своих бронирований | Нет | Да | Да |
| Изменение чужих бронирований | Нет | Нет | Да |
| Удаление чужих бронирований | Нет | Нет | Да |
| Управление комнатами | Нет | Нет | Да |
| Управление пользователями | Нет | Нет | Да |

Права доступа проверяются на сервере. Ограничения интерфейса не заменяют серверную проверку.

## 7. Коды ответов HTTP

| Код | Значение |
|---|---|
| 200 | Запрос успешно выполнен |
| 201 | Запись создана |
| 204 | Запрос выполнен, тело ответа отсутствует |
| 400 | Некорректный запрос или идентификатор |
| 401 | Отсутствующий или недействительный токен, неверные данные входа |
| 403 | Недостаточно прав доступа |
| 404 | Запись или маршрут не найдены |
| 409 | Конфликт данных |
| 422 | Ошибка проверки данных |
| 500 | Внутренняя ошибка сервера |

Пример ответа при ошибке авторизации:

```json
{
    "error": "Требуется авторизация",
    "errors": {}
}
```

## 8. Журнал входов

Результаты попыток входа записываются в файл storage/login.log.

Для каждой попытки сохраняются время, электронная почта и результат входа (success или failed).

Пароли и токены в журнал не записываются. Файл журнала исключён из Git.
